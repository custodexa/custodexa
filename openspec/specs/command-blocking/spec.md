# command-blocking

## Purpose

危險指令的連線內即時阻斷。
## Requirements
### Requirement: 指令阻斷
規則 action=block 且互動指令命中時，系統 SHALL 不將該行指令送往目標主機，SHALL 向使用者終端注入可讀警告，SHALL 記錄 blocked 事件並照常推送告警。

阻斷所產生的告警 SHALL 經與比對路徑相同的告警寫入介面落地，SHALL NOT 直接寫入告警資料表而繞過該介面——繞過會使阻斷告警不進入外送鏈，導致「被阻斷的危險指令」這類最高價值的證據只存在本機一份。經統一介面後，阻斷告警 SHALL 與比對告警同樣受既有 syslog 轉發規則涵蓋（轉發啟用時，阻斷告警於資料庫寫入成功後 SHALL 被轉發至 syslog 目的地）。

阻斷告警的紀錄內容 SHALL 與比對告警同構：SHALL 帶命中規則名稱、處置欄與所屬資產（資產可為空時 SHALL 以可辨識「無值」的形態儲存，SHALL NOT 以 0 代表無值）；兩條路徑的處置欄語義 SHALL 一致，SHALL NOT 一條留空一條填值。批次產生的告警 SHALL 以批次介面一次寫入，SHALL NOT 被拆成逐筆寫入。告警寫入介面未被注入時系統 SHALL 啟動失敗，SHALL NOT 降級為無操作而靜默丟棄阻斷告警。

改密流程借用告警通道傳遞失敗通知的既有路徑（不入庫、不轉發）SHALL NOT 被併入本介面，以免產生無對應規則的幽靈告警紀錄。

注入終端與錄影的阻斷警告，在由自動化主體以整行送入（無逐字回顯）的會話中 SHALL 帶被攔下的指令原文；人類逐字鍵入的會話因回顯已留痕，警告內容維持規則名稱即可。

#### Scenario: 阻斷危險指令
- **WHEN** 使用者鍵入命中 block 規則的指令並按 Enter
- **THEN** 指令不在目標執行、終端顯示阻斷警告、審計含 blocked 記錄

#### Scenario: alert 規則不受影響
- **WHEN** 指令命中 action=alert 規則
- **THEN** 行為與現行一致（執行+告警）

#### Scenario: 阻斷告警外送 syslog
- **WHEN** syslog 轉發已啟用，且使用者鍵入命中 block 規則的指令
- **THEN** 該阻斷告警寫入資料庫後被轉發至 syslog 目的地，與比對路徑產生的告警同軌，不再只存本機一份

#### Scenario: 兩條路徑的告警欄位同構
- **WHEN** 分別由阻斷路徑與比對路徑針對同一規則產生告警
- **THEN** 兩筆紀錄皆帶規則名稱、處置欄與資產欄，處置欄語義一致；資產不適用時該欄為可辨識的無值而非 0

#### Scenario: 告警介面未注入即啟動失敗
- **WHEN** 組裝層未注入告警寫入介面
- **THEN** 服務啟動失敗，SHALL NOT 以無操作實作啟動而使阻斷告警靜默消失

#### Scenario: 自動化主體的阻斷警告帶指令原文
- **WHEN** agent 會話整行送入命中 block 規則的指令
- **THEN** 錄影中的阻斷警告含規則名稱與該指令原文；同一規則由人類逐字鍵入時警告內容不變

### Requirement: 阻斷比對協議分流
指令阻斷（command-blocking）的規則比對 SHALL 依當前會話協議分流，僅以適用該協議的 block 規則進行；阻斷器 SHALL 取得會話協議（由 asset.Protocol 注入）以供比對。此確保 shell block 規則不誤攔 DB 會話、DB block 規則不誤攔 shell 會話。

#### Scenario: DB 會話不套 shell block 規則
- **WHEN** 一條 ssh,k8s 限定的 block 規則存在，且使用者在 mysql 會話送出含相同字面值的 SQL
- **THEN** 該 SQL 不被該 shell 規則阻斷

### Requirement: 阻斷比對涵蓋一次輸入中的每一行
指令阻斷 SHALL 對一次輸入（單一輸入幀）中每一個已提交的行逐一比對 block 規則。任一可判讀的行命中 block 規則時，該次輸入 SHALL 整體不轉送至目標，並依既有阻斷流程注入警告、記錄 blocked 事件與告警。輸入未被阻斷時，最後一個換行之後尚未提交的殘段 SHALL 保留，與下一次輸入接續組成完整的行；輸入被阻斷時，該次輸入的全部內容（含殘段）與行解析狀態 SHALL 一併捨棄，SHALL NOT 接續到下一次輸入。

括號貼上模式的開始與結束標記 SHALL 視為透明，SHALL NOT 使所包住的行被當成無法判讀。游標移動、刪字等未被追蹤的編輯控制字元 SHALL 使所在行被視為無法判讀（與跳脫序列同一語義）。

由 agent 主體經工具呼叫送出的單行命令，於去除尾端換行後 SHALL NOT 含有換行、回車、跳脫字元或其他控制字元；違反時 SHALL 以既有參數驗證錯誤拒絕，SHALL NOT 送入會話。

#### Scenario: 多行輸入的後續行命中規則
- **GIVEN** 存在適用人類的 block 規則
- **WHEN** 使用者在一次輸入中送出兩行，第一行不命中、第二行命中該規則
- **THEN** 整次輸入未送達目標，第一行亦不執行，終端顯示阻斷警告，產生 blocked 事件

#### Scenario: 多行輸入的後續行與下一次輸入接續後命中
- **GIVEN** 存在適用人類的 block 規則
- **WHEN** 使用者在一次輸入中送出一個不命中的完整行與一段未提交的殘段，再於下一次輸入送出餘下部分與換行，接續後的整行命中規則
- **THEN** 接續後的整行被比對並阻斷，產生 blocked 事件

#### Scenario: 括號貼上的首行命中規則
- **GIVEN** 目標 shell 開啟括號貼上，存在適用人類的 block 規則
- **WHEN** 使用者貼上首行命中該規則的多行文字
- **THEN** 該次輸入未送達目標，產生 blocked 事件

#### Scenario: 跨輸入接續的行
- **WHEN** 使用者分兩次輸入送出一行命中規則的命令，第一次不含換行
- **THEN** 組成的整行被比對並阻斷

#### Scenario: 被阻斷輸入的殘段不接續到下一次輸入
- **GIVEN** 存在適用人類的 block 規則
- **WHEN** 一次輸入含命中規則的行及其後未提交的殘段而被阻斷，下一次輸入再送出命中規則的完整行
- **THEN** 下一次輸入同樣被阻斷、未送達目標，產生 blocked 事件

#### Scenario: 不命中的多行貼上照常送出
- **WHEN** 使用者一次貼上三行都不命中任何 block 規則的指令
- **THEN** 整段照常送達並依序執行

#### Scenario: agent 多行命令被拒
- **WHEN** agent 以工具呼叫送出含內嵌換行的多行命令
- **THEN** 回參數驗證錯誤，命令未送入會話

#### Scenario: agent 單行命令照常
- **WHEN** agent 送出不含控制字元的單行命令（可帶尾端換行）
- **THEN** 命令照常送入會話並受 block 規則比對
