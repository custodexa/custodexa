# deployment-upgrade Specification

## Purpose
規範管理腳本的升級流程：升級入口與版本規則、停機前的稽核排空關卡、升級前備份與快照（含自備備份的一致性確認）、既有 git clone 部署的一次性首次轉換與失敗時的手動退回，以及升級後核對、失敗即停下而不自動回退。

## Requirements

### Requirement: 升級入口與既有 git clone 部署

`custodexa.sh upgrade` 不帶參數時，在安裝包部署上 SHALL 只查詢最新版且不做任何變更；查詢 SHALL 驗發行清單的校驗和，有 cosign 時驗簽章，未驗簽章時 SHALL 明示結果未經來源驗證，校驗和不符時 SHALL NOT 給出升級資格結論。偵測到既有 git clone 部署時，不帶參數、帶版號或帶安裝包路徑 SHALL 一律進入轉換預覽，SHALL NOT 落入只查詢；非互動且不帶參數時 SHALL 拒絕。升級 SHALL 由目標版本的腳本執行，舊腳本只取得並驗證新安裝包。

#### Scenario: 舊部署下不帶參數
- **WHEN** 在 1.12.4 git clone 部署根以 1.13.0 安裝包的腳本執行 `upgrade`
- **THEN** 出現轉換預覽，目標為 1.13.0，回答 y 之前沒有任何變更

#### Scenario: 查詢時沒有 cosign
- **WHEN** 在沒有 cosign 的安裝包部署執行 `upgrade`
- **THEN** 結果標示只驗了校驗和、未經來源驗證

### Requirement: 版本規則

目標版本低於目前版本 SHALL 拒絕，並說明以升級前的備份依備份還原程序手動還原；等於目前版本 SHALL 拒絕；目前版本低於目標 MANIFEST 的最低來源版本 SHALL 拒絕並印出須先升的中繼版本。

#### Scenario: 跳版過多
- **WHEN** 目前 1.12.9、目標 1.14.0 的最低來源版本為 1.13.0
- **THEN** 腳本拒絕且無任何變更，並印出先升 1.13.0 的指令

### Requirement: 停機前的稽核排空關卡

升級 SHALL 先確認稽核佇列深度為 0 才停止服務，逾時即停下且服務維持運作。讀不到佇列指標時，只有明確讀到封存狀態、且可確認本次行程從未裝配稽核佇列時 SHALL 放行；封存狀態讀取被拒、逾時、無法解析、曾解封後再封存等狀態未知情形 SHALL 停下，不停機、不變更。`--yes` SHALL NOT 略過此關卡。

#### Scenario: 封存狀態讀取被來源位址限制擋下
- **WHEN** 佇列指標不存在，且封存狀態查詢回 403
- **THEN** 升級停在排空步驟，服務仍運作，畫面說明無法確認

### Requirement: 升級前備份與快照

升級 SHALL 依序排空、停止、備份，再換版。預設由腳本做完整停機備份並驗證可讀；備份前 SHALL 記下 `schema_migrations`、使用者／連線／稽核筆數與四把金鑰指紋。指紋 SHALL 與金鑰清冊頁同算法；任一指紋算不出或來源不唯一時，快照 SHALL 標為不可用，之後的金鑰核對 SHALL NOT 判為通過，改列人工核對。備份空間不足 SHALL 在停機前擋下。

#### Scenario: 金鑰指紋來源不唯一
- **WHEN** 資料庫中有兩列狀態為 active 的資料金鑰
- **THEN** 快照標為不可用，升級後的金鑰項顯示無法核對並列入人工核對，不顯示通過

### Requirement: 自備備份的一致性確認

選擇自備備份時，腳本 SHALL 在排空並停機之後才接受備份識別，並 SHALL 列出排空確認時間、停機時間與備份必須涵蓋的資料目錄、`.env`、`tls/`（外接資料庫形態另含資料庫備份）。維運 SHALL 提供備份識別、開始時間與還原程序位置並確認涵蓋；開始時間早於停機時間 SHALL 停下。非互動時 `--backup-ref` SHALL 與 `--backup-time`、`--backup-restore` 並用，且服務在腳本開始時仍執行者 SHALL 拒絕。

#### Scenario: 快照早於停機
- **WHEN** 維運輸入的快照開始時間早於腳本記錄的停機時間
- **THEN** 腳本停下並說明該快照缺停機前最後寫入的資料，服務維持停止並印出恢復指令

### Requirement: 首次轉換的前提與搬移

轉換 SHALL 只在 git 工作樹乾淨時進行：`git status --porcelain` 除腳本自己寫入的備份資料夾、鎖檔與暫存的安裝包資料夾外有任何輸出時，SHALL 在預覽前拒絕、列出 git 報告的項目，且不做任何變更。轉換 SHALL 在排空、停機、備份之後進行；停止與移除舊容器 SHALL 使用舊部署的 compose 專案名與根目錄 compose 檔。`.git` 與 git 追蹤的頂層項目 SHALL 搬進 `releases/<舊版>/`；資料目錄、`.env`、`tls/`、備份與紀錄 SHALL 留在原位，資料目錄 SHALL NOT 被搬移或改名。`.env` 只改寫以主機路徑內插的鍵為絕對路徑並設定 `COMPOSE_FILE`、`COMPOSE_PROJECT_NAME`，改前另存一份，並記錄鍵名、行號、舊值與新值。

#### Scenario: 轉換時根目錄仍是舊結構
- **WHEN** 轉換開始時根目錄沒有 `current/compose.yml`
- **THEN** 停止與 `down` 以舊專案名與根目錄 `docker-compose.yml` 執行，成功停下舊服務

#### Scenario: 工作樹有改動
- **WHEN** git 回報產品檔被改過或有未追蹤的檔
- **THEN** 升級在預覽前停下並列出那些項目，沒有停止任何服務、沒有任何變更

### Requirement: 轉換失敗時的手動退回

轉換在搬動任何檔案之後失敗或中斷時，腳本 SHALL 停下並印出依序執行即可把目錄還原成 git clone 結構的指令、升級前備份的位置，以及只在核對 git 狀態沒有其他項目後才以舊專案名與舊 compose 啟動舊版的指令；SHALL NOT 自行還原或啟動。下次執行時偵測到轉換停在一半，SHALL 只印同一組指令並拒絕其他動作。

#### Scenario: 搬移到一半失敗
- **WHEN** 轉換在搬移產品檔時失敗
- **THEN** 依畫面指令執行後，目錄與 git 狀態回到轉換前，舊版可用印出的指令啟動

### Requirement: 升級後核對且失敗停下不自動回退

升級後 SHALL 核對服務、版本、執行中 image ID、`schema_migrations` 為升級前的超集、筆數、四指紋與單一實例鎖。偵測到新版接到空資料庫時 SHALL 立即停止全部服務並停下。任何失敗 SHALL 停下並印出可複製的恢復指令，或升級前備份的位置與依備份還原程序手動還原的說明，SHALL NOT 自動回退。

#### Scenario: 新版接到空資料庫
- **WHEN** 升級後使用者筆數降為 1 而升級前多於 1
- **THEN** 全部服務被停止，畫面指出資料目錄設定與回到升級前版本的方式，資料未被改動
