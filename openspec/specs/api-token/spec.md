# api-token Specification

## Purpose
定義個人 API token：持有管理類角色的人為自己建立、供程式化工具呼叫管理與設定 API 的憑證。涵蓋建立資格與授權範圍、可呼叫的端點、對所屬帳號本人的保護、撤銷與失效、稽核歸因、高權限告警，以及建立、檢視與撤銷的畫面行為。
## Requirements
### Requirement: API token 的建立資格

系統 SHALL 允許人類帳號為自己建立 API token，條件是該帳號在建立當下至少持有一個管理類角色的有效指派（直接指派或經使用者群組取得皆可）。資格 SHALL 在建立的寫入交易內重新判定。AI agent 主體 SHALL NOT 建立或持有 API token。系統 SHALL NOT 提供替他人建立 API token 的途徑；以 API token 認證的請求 SHALL NOT 建立或撤銷 API token。帳號的來源（本地、目錄服務或外部身分提供者）不影響建立資格。

#### Scenario: 持有管理類角色者建立成功
- **WHEN** 一個持有資產管理類角色的人類帳號以登入工作階段送出建立請求，名稱、授權角色與到期選擇皆合法
- **THEN** 系統建立 API token 並回應 201，回應含一次性明文

#### Scenario: 沒有管理類角色者被拒
- **WHEN** 一個只持有非管理類角色的人類帳號送出建立請求
- **THEN** 系統拒絕、不建立任何資料，回應不含明文

#### Scenario: 不能替他人建立
- **WHEN** 任何主體（含超級管理者）嘗試以他人帳號為擁有者建立 API token
- **THEN** 系統沒有可達成此事的端點或欄位；請求中夾帶的其他帳號識別不被採信

#### Scenario: API token 不能用來建立 API token
- **WHEN** 以 API token 認證的請求呼叫建立或撤銷 API token 的端點
- **THEN** 系統回 403，不建立也不撤銷

### Requirement: 授權角色只能來自本人擁有的管理類角色

建立 API token 時 SHALL 指定一組授權角色。授權角色 SHALL 全部屬於請求者當下持有的管理類角色；任一角色不屬於此集合時，系統 SHALL 整筆拒絕。授權角色 SHALL 至少一個。非管理類角色 SHALL NOT 可被授權。建立後授權角色 SHALL NOT 可修改。

#### Scenario: 選擇部分角色
- **WHEN** 持有兩個管理類角色的帳號建立 API token 並只授權其中一個
- **THEN** 該 token 的授權角色只有被選的那一個

#### Scenario: 夾帶未持有的角色
- **WHEN** 建立請求的授權角色含請求者未持有的角色
- **THEN** 系統整筆拒絕，不建立 token

#### Scenario: 未選任何角色
- **WHEN** 建立請求的授權角色為空
- **THEN** 系統拒絕並指出須至少選擇一個角色

### Requirement: API token 的有效權限即時跟隨本人

以 API token 認證的請求，其有效權限 SHALL 等於「該 token 的授權角色」與「所屬帳號當下實際持有的角色指派」的交集，並以所屬帳號當下的指派範圍為準。所屬帳號的某個角色被收回時，token SHALL 立即失去該角色；同一角色之後再被指派回來時，token SHALL 自動恢復該角色。所屬帳號新取得、但 token 未被授權的角色，token SHALL NOT 取得。內建身分（例如超級管理者）SHALL 只由交集後的指派決定：token 未被授權對應角色時，即使所屬帳號持有該身分，請求也不具備該身分。此交集 SHALL 適用於處理該請求時對操作者的所有授權判定，含寫入交易內的重新驗證，以及端點本身只要求較基本的能力、而由內部關卡另行判定的進階能力（例如指派角色、掛載憑證、寫入秘密）；以 API token 建立改密計劃、對計劃做任何更新或承接計劃時，請求 SHALL 對該計劃最新的目標具備執行所需的能力與範圍，否則系統 SHALL 拒絕且不寫入任何變更；對被操作帳號的保護資格判定 SHALL 以該帳號的完整身分為準，不受操作者 token 的授權角色影響。交集為空時，請求 SHALL NOT 具備任何能力，含系統給予沒有任何角色的帳號的基本能力。授權角色 SHALL 以角色的識別為準：角色被刪除後 token 永久失去該角色，之後建立的同名角色 SHALL NOT 被 token 繼承。某個授權角色是否有效 SHALL 以所屬帳號當下是否仍有該角色的有效指派判定，直接指派與經使用者群組取得皆算。

#### Scenario: 交集為空的 token 沒有任何能力
- **WHEN** token 的授權角色全部從所屬帳號被收回，隨後以該 token 呼叫一個沒有任何角色的帳號也能呼叫的端點
- **THEN** 系統以能力不足拒絕

#### Scenario: 同一角色有兩個來源
- **WHEN** 所屬帳號同時經直接指派與使用者群組持有某個角色，管理者收回直接指派，隨後以授權了該角色的 token 呼叫需要該角色能力的端點
- **THEN** 請求通過授權判定

#### Scenario: 角色刪除後同名重建
- **WHEN** token 授權的某個角色被刪除，之後建立一個同名的新角色並指派給所屬帳號
- **THEN** token 不具備新角色的能力

#### Scenario: 內部關卡判定的能力同樣受限
- **WHEN** 所屬帳號持有帳號管理角色與另一個含角色指派能力的角色，token 只被授權帳號管理角色，並以該 token 替另一個帳號指派角色
- **THEN** 系統以能力不足拒絕

#### Scenario: 沒有執行能力的 token 不能建立改密計劃
- **WHEN** 所屬帳號持有改密計劃管理與改密執行兩種能力（來自不同角色），token 只被授權含計劃管理能力的角色，並以該 token 建立一筆啟用的改密計劃
- **THEN** 系統以能力不足拒絕，不建立計劃

#### Scenario: 沒有執行能力的 token 不能藉更新讓計劃進入排程
- **WHEN** 一筆已啟用但尚未設定排程時間的改密計劃存在，token 只被授權含計劃管理能力的角色而所屬帳號另有改密執行能力，以該 token 只更新該計劃的排程時間或名稱
- **THEN** 系統以能力不足拒絕，計劃的內容、授權紀錄與待重新授權的狀態皆不變

#### Scenario: 經 token 建立的排程工作歸屬於帳號
- **WHEN** 以 token 建立一筆改密計劃後撤銷該 token
- **THEN** 該計劃仍存在並依排程執行，執行前的權限以所屬帳號當下的角色判定

#### Scenario: 被操作帳號的保護不因 token 而放寬
- **WHEN** 同時持有超級管理者與帳號管理角色的帳號，以只授權帳號管理角色的 token 對另一個超級管理者帳號執行只限超級管理者的帳號操作
- **THEN** 系統拒絕，回應與一個只持有帳號管理角色的帳號親自操作時相同

#### Scenario: 只授權部分角色的 token 不具其他角色的能力
- **WHEN** 所屬帳號持有資產管理與授權管理兩個角色，token 只被授權資產管理，並以該 token 呼叫需要授權管理能力的端點
- **THEN** 系統以能力不足拒絕

#### Scenario: 角色被收回後立即失去
- **WHEN** 管理者收回所屬帳號的某個管理類角色，隨後以授權了該角色的 token 呼叫需要該角色能力的端點
- **THEN** 系統以能力不足拒絕

#### Scenario: 角色指派回來後自動恢復
- **WHEN** 被收回的角色重新指派給所屬帳號，隨後以同一把 token 呼叫需要該角色能力的端點
- **THEN** 請求通過授權判定，不需重新建立 token

#### Scenario: 範圍跟隨本人
- **WHEN** 所屬帳號某角色的節點範圍被縮小，隨後以授權了該角色的 token 操作縮小後範圍以外的資產
- **THEN** 系統回應與所屬帳號本人以同一角色操作範圍外資產時相同

#### Scenario: 超級管理者的 token 未授權對應角色時不是超級管理者
- **WHEN** 所屬帳號持有超級管理者身分與另一個管理類角色，token 只被授權後者，並呼叫只限超級管理者的端點
- **THEN** 系統拒絕

### Requirement: 到期時間

建立 API token 時 SHALL 明確指定到期時刻，或明確指定永不到期；兩者皆未指定的請求 SHALL 被拒絕。到期時刻 SHALL 在未來。系統 SHALL NOT 對到期時刻設上限。到期後的 token SHALL 無法通過認證。建立後到期時間 SHALL NOT 可修改。

#### Scenario: 指定到期時刻
- **WHEN** 建立請求帶一個未來的到期時刻
- **THEN** token 在該時刻之前可用，之後認證失敗

#### Scenario: 永不到期
- **WHEN** 建立請求明確指定永不到期
- **THEN** token 不因時間經過而失效，清單與稽核以「永不到期」呈現

#### Scenario: 未選擇到期
- **WHEN** 建立請求既無到期時刻也未指定永不到期
- **THEN** 系統拒絕並指出須選擇到期時間

### Requirement: 名稱

API token SHALL 具備名稱，長度 1 至 100 字元。同一帳號下，占用中的 API token 名稱 SHALL NOT 重複；重複時系統 SHALL 回 409。占用中指未撤銷、未到期且未因還原備份而失效；因帳號停用或角色收回而暫停的 token 仍占用其名稱。已撤銷、已到期或已因還原失效的 token，其名稱 SHALL 可再次使用。同一帳號同時送出的多個同名建立請求 SHALL 至多一個成功。

#### Scenario: 同時建立同名 token
- **WHEN** 同一帳號同時送出兩個名稱相同的建立請求
- **THEN** 恰有一個成功，另一個回 409

#### Scenario: 暫停中的 token 仍占用名稱
- **WHEN** 名為 `terraform-apply` 的 token 因授權角色被收回而暫停，再建立同名 token
- **THEN** 系統回 409

#### Scenario: 與可用 token 同名
- **WHEN** 帳號已有一把名為 `terraform-apply` 的可用 token，再建立同名 token
- **THEN** 系統回 409，不建立

#### Scenario: 重用已失效的名稱
- **WHEN** 名為 `terraform-apply` 的 token 已撤銷，再建立同名 token
- **THEN** 建立成功

### Requirement: 明文只交付一次

系統 SHALL 只在建立回應中交付一次 API token 明文，該回應 SHALL 帶 `Cache-Control: no-store`。系統 SHALL 只保存明文的雜湊，SHALL NOT 以任何可還原的形式保存明文。清單、稽核、告警與任何其他回應 SHALL NOT 含明文或雜湊。明文 SHALL 帶固定且與其他憑證種類不同的前綴，供憑證掃描工具辨識。

#### Scenario: 建立後無法再取得明文
- **WHEN** token 建立完成後，本人或任何管理者讀取該 token 的清單或詳情
- **THEN** 回應不含明文與雜湊

#### Scenario: 稽核與告警不含明文
- **WHEN** 檢視建立事件的稽核列與隨之產生的告警
- **THEN** 其內容不含明文與雜湊

### Requirement: 以 API token 認證

系統 SHALL 接受以 `Authorization: Bearer` 攜帶 API token 的請求，並於每次請求現查 token、所屬帳號與來源位址，SHALL NOT 快取認證結果。下列任一情況 SHALL 認證失敗：token 不存在、已撤銷、已到期、建立於目前還原世代之前；所屬帳號不是人類帳號、已刪除或已停用；請求來源不在所屬帳號的允許來源網段內。所有認證失敗 SHALL 回同一個 401 錯誤碼，真實原因 SHALL 只記入稽核。認證失敗的留痕 SHALL 沿用系統對未認證請求的有界留痕：同一來源的大量失敗 SHALL 受限流並可聚合為摘要，SHALL NOT 因失敗請求的數量而無上限地寫入。認證成功的請求 SHALL 以所屬帳號為操作者。系統 SHALL 記錄 token 的最近使用時間與來源位址；此紀錄 SHALL NOT 作為放行條件，其寫入失敗 SHALL NOT 使請求失敗。

#### Scenario: 有效 token 通過認證
- **WHEN** 以未撤銷、未到期的 token 自允許的來源呼叫一個開放端點，且所屬帳號具備該端點所需能力
- **THEN** 請求成功，操作者為所屬帳號

#### Scenario: 已撤銷的 token
- **WHEN** 以已撤銷的 token 呼叫任何端點
- **THEN** 系統回 401，回應不透露撤銷這個原因

#### Scenario: 來源不在允許網段
- **WHEN** 所屬帳號設有允許來源網段，以 token 自清單外的位址呼叫
- **THEN** 系統回 401，稽核記下來源不符

#### Scenario: 還原備份後的舊 token
- **WHEN** 系統以管理腳本還原備份後，以還原前建立的 token 呼叫
- **THEN** 系統回 401；清單將該 token 標示為已因還原失效

#### Scenario: 大量失敗請求的留痕有上限
- **WHEN** 同一來源在短時間內以不存在或已撤銷的 token 送出大量請求
- **THEN** 每個請求皆回 401；稽核中的對應紀錄數量受限流約束，超出部分聚合為摘要，原因仍可追溯

### Requirement: API token 可呼叫的端點範圍

以 API token 認證的請求 SHALL 只能呼叫登錄為開放的管理與設定端點。此登錄 SHALL 為封閉清單並涵蓋系統的每一條路由，含不需登入的路由與連線入口；未登錄或登錄為不開放的路由，系統 SHALL 對 API token 請求回 403。新增路由 SHALL 預設不開放。下列端點 SHALL NOT 開放：連線票證的簽發與所有連線入口、錄影與鍵盤紀錄的內容、剪貼簿內容與其他機敏內容的調閱、解封與金鑰操作、連線申請與其簽核、稽核簽核與告警審閱、登入與工作階段端點、AI agent 鑰匙的管理、API token 的建立與撤銷，以及會讓系統以保存的憑證或秘密對外發起連線的動作（資產連線測試、系統專用帳號的登入測試、立即執行的改密、建立即執行的改密批次、以保存的秘密向資產查詢執行中工作負載、目錄服務與通知通道及離機儲存的測試與重試）。立即產出報告的動作、以及會回傳合規判定現況的預覽 SHALL NOT 開放。下列端點同樣 SHALL NOT 開放：讓系統對請求指定的位址發出連線的探測；主機身分的採用與重置；目錄服務連線設定的寫入與刪除；離機儲存設定的寫入；系統安全告警分級的寫入；系統專用帳號設定的寫入；把系統保存的既有憑證掛載或改綁到資產帳號。改密計劃、通知通道、日誌轉發目的地與身分來源映射規則的建立與修改 SHALL 屬於可開放的管理與設定端點。端點範圍的限制 SHALL 與端點本身的權限檢查並存，兩者皆通過才放行。

#### Scenario: 開放的管理端點
- **WHEN** 以具備資產管理能力的 token 建立一筆資產
- **THEN** 請求成功

#### Scenario: 不能簽發連線票證
- **WHEN** 以 token 呼叫連線票證簽發端點
- **THEN** 系統回 403，不簽發

#### Scenario: 不能讀取錄影內容
- **WHEN** 以所屬帳號具備檢視能力的 token 呼叫錄影內容端點
- **THEN** 系統回 403

#### Scenario: 新路由預設不開放
- **WHEN** 系統新增一條路由而未在登錄中宣告其對 API token 的開放與否
- **THEN** 建置期的檢查失敗；該路由在登錄前對 API token 不開放

#### Scenario: 不需登入的路由也受範圍限制
- **WHEN** 以有效的 token 呼叫一條不需登入、且未登錄為開放的路由
- **THEN** 系統回 403

#### Scenario: 不能觸發連線測試
- **WHEN** 以具備資產管理與測試能力的 token 呼叫資產連線測試端點
- **THEN** 系統回 403，不對資產發起連線

#### Scenario: 不能改動目錄服務連線設定
- **WHEN** 以具備對應能力的 token 寫入目錄服務的連線設定
- **THEN** 系統回 403，設定不變；以同一把 token 讀取該設定成功

#### Scenario: 不能立即產出報告
- **WHEN** 以具備報告排程管理能力的 token 建立一筆報告排程，再呼叫該排程的立即產出
- **THEN** 建立成功；立即產出回 403

#### Scenario: 不能調整系統安全告警的分級
- **WHEN** 以授權了系統安全管理員角色的 token 變更某個系統安全告警類型的分級
- **THEN** 系統回 403，分級不變

#### Scenario: 可以管理改密計劃但不能立即執行
- **WHEN** 以具備對應能力的 token 建立一筆改密計劃，再呼叫立即執行的端點
- **THEN** 建立成功；立即執行回 403

### Requirement: API token 不能引用系統保存的既有憑證

以 API token 認證的請求建立資產、匯入資產或建立資產帳號時，SHALL NOT 以識別引用系統保存的既有憑證；帶有此種引用的請求系統 SHALL 整筆拒絕並回 403，不建立任何資料；匯入的預覽與提交 SHALL 同樣拒絕，且不論請求者的憑證掛載能力來自全系統或節點範圍的指派。以請求自帶的秘密建立資產與資產帳號 SHALL NOT 受本需求限制。本需求 SHALL NOT 改變以登入工作階段操作時的行為。

#### Scenario: 引用既有憑證建立資產帳號
- **WHEN** 以具備資產與憑證管理能力的 token 建立一筆資產帳號，並以識別引用一筆既有的共用憑證
- **THEN** 系統回 403，不建立資產帳號，該憑證的掛載不變

#### Scenario: 匯入資料中引用既有憑證
- **WHEN** 以 token 匯入多筆資產，其中一筆以識別引用既有憑證
- **THEN** 系統拒絕整筆匯入，不建立任何資產

#### Scenario: 自帶秘密建立
- **WHEN** 以具備對應能力的 token 建立一筆資產帳號，密碼由請求自帶
- **THEN** 建立成功

#### Scenario: 節點範圍的掛載能力同樣被拒
- **WHEN** 所屬帳號的憑證掛載能力只來自節點範圍的角色指派，以授權了該角色的 token 匯入一筆引用該範圍內既有憑證的資產
- **THEN** 預覽與提交皆回 403，不建立任何資產

#### Scenario: 以登入工作階段引用既有憑證
- **WHEN** 同一帳號以登入工作階段建立資產帳號並引用既有憑證
- **THEN** 行為與加入本功能之前相同

### Requirement: API token 不能改動所屬帳號本人的登入與存取設定

以 API token 認證的請求，對象為該 token 的所屬帳號時，系統 SHALL 拒絕下列變更並回 403：設定或重設密碼、停用或重設兩步驟驗證、變更登入方式（改為僅外部登入、綁定或解除外部身分）、變更允許來源網段、停用或刪除帳號、變更閒置自動停用的豁免、變更角色。所屬帳號在某個身分來源有外部身分（由該來源建立，或已綁定該來源的身分）時，以其 API token 寫入該身分來源的映射規則（外部群組對角色、外部群組對使用者群組的建立、修改、啟停與刪除）或建立、變更、刪除該來源的提供者設定，系統 SHALL 拒絕並回 403；其他身分來源不受限制。目錄服務來源的帳號 SHALL 一律視為在目錄服務來源有外部身分，不論其是否曾命中任何映射；外部身分提供者來源 SHALL 以帳號外部身分的簽發者與用戶端識別是否與該提供者相同判定，提供者設定重建後亦同。沒有任何外部身分的本地帳號 SHALL NOT 受此限制。以 API token 把所屬帳號經映射取得的角色改為手動指派，系統 SHALL 拒絕。解除帳號鎖定 SHALL NOT 受本需求限制。本需求 SHALL NOT 涵蓋角色權限內容的改寫與全系統安全政策的調整。角色的變更 SHALL 含直接指派，以及經使用者群組改變該帳號有效角色的途徑：把該帳號加入或移出帶有角色的群組、變更該帳號所屬群組的角色、刪除該帳號所屬且帶有角色的群組。請求帶有上述欄位但值與現況相同時 SHALL NOT 視為變更。所屬帳號的其他欄位，以及對其他帳號的操作，SHALL NOT 受本需求限制。本需求 SHALL NOT 改變以登入工作階段操作時的行為。

#### Scenario: 不能清除自己的來源限制
- **WHEN** 所屬帳號設有允許來源網段，以具備帳號管理能力的 token 自允許的來源送出更新，將該帳號的允許來源網段清空
- **THEN** 系統回 403，來源限制不變

#### Scenario: 不能重設自己的密碼或停用兩步驟驗證
- **WHEN** 以具備帳號管理能力的 token 對所屬帳號呼叫重設密碼或停用兩步驟驗證
- **THEN** 系統回 403，密碼與兩步驟驗證不變

#### Scenario: 不能替自己加角色
- **WHEN** 以具備角色指派能力的 token 替所屬帳號新增一個角色
- **THEN** 系統回 403，角色指派不變

#### Scenario: 不能經群組替自己加角色
- **WHEN** 以具備群組管理與角色指派能力的 token 把所屬帳號加入一個帶有角色的使用者群組
- **THEN** 系統回 403，群組成員不變

#### Scenario: 不能替自己綁定外部身分
- **WHEN** 以具備帳號管理能力的 token 替所屬帳號綁定一個外部身分
- **THEN** 系統回 403，外部身分不變

#### Scenario: 不能豁免自己的閒置停用
- **WHEN** 以具備帳號管理能力的 token 把所屬帳號設為不受閒置自動停用約束
- **THEN** 系統回 403，豁免設定不變

#### Scenario: 不能改動自己所屬身分來源的映射規則
- **WHEN** 所屬帳號是由某個外部身分來源建立的帳號，以具備身分來源管理與角色指派能力的 token 刪除該來源的一條映射規則
- **THEN** 系統回 403，規則不變，任何帳號的角色不變

#### Scenario: 目錄服務來源的帳號尚未命中任何映射
- **WHEN** 所屬帳號是目錄服務來源的帳號，目前沒有任何角色來自映射，以具備對應能力的 token 新增一條目錄服務來源的映射規則
- **THEN** 系統回 403，規則不建立

#### Scenario: 不能重建與自己外部身分相同來源的提供者設定
- **WHEN** 所屬帳號有一筆外部身分，其簽發者與用戶端識別所對應的提供者設定目前不存在，以具備對應能力的 token 建立一個簽發者與用戶端識別相同的提供者設定
- **THEN** 系統回 403，設定不建立

#### Scenario: 已綁定外部身分的本地帳號
- **WHEN** 所屬帳號是本地建立、已綁定某個外部身分提供者的身分，以具備對應能力的 token 修改該提供者來源的一條映射規則
- **THEN** 系統回 403，規則不變

#### Scenario: 其他身分來源的映射規則照常
- **WHEN** 所屬帳號是本地帳號且沒有綁定任何外部身分，以同樣能力的 token 新增一條映射規則
- **THEN** 建立成功

#### Scenario: 不能釘選自己的映射角色
- **WHEN** 以具備帳號管理與角色指派能力的 token 把所屬帳號經映射取得的角色改為手動指派
- **THEN** 系統回 403，角色的來源不變

#### Scenario: 值未變動的更新不受影響
- **WHEN** 以 token 更新所屬帳號的姓名，請求同時帶有與現況相同的允許來源網段
- **THEN** 更新成功

#### Scenario: 對其他帳號照常
- **WHEN** 以具備帳號管理能力的 token 變更另一個一般帳號的允許來源網段
- **THEN** 更新成功

#### Scenario: 本人以登入工作階段操作不受影響
- **WHEN** 同一帳號以登入工作階段在畫面上變更自己帳號的允許來源網段
- **THEN** 行為與加入本功能之前相同

### Requirement: API token 自我查驗

系統 SHALL 提供一個只接受 API token 認證的查驗端點，回報該 token 是否有效、所屬帳號名稱、建立時授權的角色、其中目前有效的角色，以及到期時間（或永不到期）。回應 SHALL NOT 含明文或雜湊。

#### Scenario: 查驗有效的 token
- **WHEN** 以有效的 token 呼叫查驗端點
- **THEN** 回應列出所屬帳號名稱、授權的角色、目前有效的角色與到期時間

#### Scenario: 部分角色已被收回
- **WHEN** token 授權了兩個角色，其中一個已從所屬帳號被收回，以該 token 呼叫查驗端點
- **THEN** 回應的授權角色有兩個，目前有效的角色只有一個

#### Scenario: 查驗無效的 token
- **WHEN** 以已到期的 token 呼叫查驗端點
- **THEN** 系統回 401，與其他認證失敗相同

### Requirement: 撤銷

本人 SHALL 能撤銷自己的 API token。具帳號管理能力的人 SHALL 能撤銷他人的 API token，並能一次撤銷某個帳號全部尚可使用的 token。所屬帳號持有超級管理者或系統安全管理員身分（任一來源）時，他人對其 token 的撤銷 SHALL 只限超級管理者。撤銷 SHALL 不可復原且冪等，SHALL 可附原因；撤銷後的下一次請求 SHALL 認證失敗。撤銷 SHALL 記錄撤銷者與時間。

#### Scenario: 本人撤銷
- **WHEN** 本人撤銷自己的一把可用 token
- **THEN** 該 token 立即無法通過認證，清單顯示已撤銷、撤銷者與時間

#### Scenario: 管理者撤銷他人的 token
- **WHEN** 具帳號管理能力的人撤銷一個一般管理者的 token 並填寫原因
- **THEN** 撤銷成功，原因留在紀錄中，本人的清單顯示是誰撤銷的

#### Scenario: 受保護帳號的 token
- **WHEN** 非超級管理者嘗試撤銷一個超級管理者帳號的 token
- **THEN** 系統拒絕，token 仍可使用

#### Scenario: 重複撤銷
- **WHEN** 對已撤銷的 token 再次送出撤銷
- **THEN** 回應與首次撤銷的結果一致，紀錄不被覆寫

### Requirement: 帳號狀態與 API token 的連動

所屬帳號被停用期間，其 API token SHALL 無法通過認證；帳號重新啟用後，未到期也未撤銷的 token SHALL 恢復可用，不需重新建立。所屬帳號被刪除時，其 API token SHALL 失效。token 的授權角色全部被收回時，token SHALL 呈現為暫停而非失效，並在角色指派回來後恢復。清單 SHALL 區分下列狀態：有效、即將到期、已到期、已撤銷、已因還原失效、因帳號停用而暫停、因角色收回而暫停。一把 token 同時符合多種狀態時，SHALL 依下列順序取最前者呈現：已撤銷、已因還原失效、已到期、因帳號停用而暫停、因角色收回而暫停、即將到期、有效。所屬帳號的其他認證事件 SHALL NOT 影響既有 token：變更或重設密碼、帳號因登入失敗被鎖定、被要求下次登入時變更密碼、被要求註冊兩步驟驗證、登出全部裝置、改為僅外部登入或解除外部身分綁定。

#### Scenario: 重設密碼不影響 token
- **WHEN** 管理者重設所屬帳號的密碼，隨後以該帳號未到期也未撤銷的 token 呼叫開放端點
- **THEN** 請求通過認證

#### Scenario: 帳號鎖定不影響 token
- **WHEN** 所屬帳號因連續登入失敗被鎖定，鎖定期間以其 token 呼叫開放端點
- **THEN** 請求通過認證

#### Scenario: 登出全部裝置不影響 token
- **WHEN** 所屬帳號的全部登入工作階段被撤銷，隨後以其 token 呼叫開放端點
- **THEN** 請求通過認證

#### Scenario: 同時符合多種狀態
- **WHEN** 一把已到期的 token 其所屬帳號又被停用
- **THEN** 清單在本人與管理者的畫面皆顯示為已到期

#### Scenario: 停用後重新啟用
- **WHEN** 帳號被停用後又被重新啟用，其間 token 未到期也未被撤銷
- **THEN** 停用期間以該 token 的請求認證失敗；重新啟用後同一把 token 的請求通過認證

#### Scenario: 帳號刪除
- **WHEN** 所屬帳號被刪除
- **THEN** 其全部 token 無法通過認證

#### Scenario: 授權角色全被收回
- **WHEN** token 的授權角色全部從所屬帳號被收回
- **THEN** 清單顯示該 token 因角色收回而暫停；以它呼叫任何需要能力的端點皆被拒；角色指派回來後恢復

### Requirement: 高權限 API token 的系統安全告警

建立的 API token 其授權角色含超級管理者或系統安全管理員時，系統 SHALL 在建立的同一交易內產生一則系統安全告警。該告警類型 SHALL 登錄於系統安全告警類型目錄，歸於身分與權限分組，預設分級為 high；管理者覆寫過此類型的分級時 SHALL 以覆寫為準。建立失敗而交易回滾時 SHALL NOT 留下告警。告警內容 SHALL 含建立者、授權的高權限角色、token 名稱與到期時間（或永不到期），SHALL NOT 含明文或雜湊。授權角色不含上述兩種角色時 SHALL NOT 產生此告警。

#### Scenario: 授權了超級管理者角色
- **WHEN** 此類型的分級未被覆寫，超級管理者為自己建立一把授權了超級管理者角色的 token
- **THEN** 建立成功，同時產生一則 high 分級的系統安全告警，並交由通知機制送往啟用中的通知通道

#### Scenario: 分級已被覆寫
- **WHEN** 管理者已將此類型的分級改為其他等級，之後有人建立一把授權了系統安全管理員角色的 token
- **THEN** 產生的告警採用覆寫後的分級

#### Scenario: 高權限者只授權一般管理角色
- **WHEN** 同時持有超級管理者與資產管理角色的帳號建立一把只授權資產管理角色的 token
- **THEN** 不產生此告警

### Requirement: 稽核

API token 的建立與撤銷 SHALL 各留一筆稽核，與建立或撤銷在同一交易內寫入，內容含 token 名稱、授權角色、到期時間與撤銷原因，SHALL NOT 含明文或雜湊。以 API token 認證的請求在處理過程中產生的每一筆稽核列（含請求層級的紀錄、各項操作在寫入交易內留下的紀錄，以及該請求啟動、於請求結束後才寫入的紀錄），SHALL 以所屬帳號為操作者，並記下所經由的 token 識別與當時的名稱；名稱 SHALL 為寫入當下的快照，token 之後被撤銷或所屬帳號被刪除時仍可讀。本人親自以登入工作階段操作的稽核列 SHALL 不帶 token 識別。經 API token 建立的排程資源於日後由系統依排程執行時，執行所產生的稽核列 SHALL 不帶 token 識別；建立或修改該資源的請求所留下的稽核列 SHALL 帶。token 識別與名稱 SHALL 受稽核列的完整性驗證保護，被竄改或清除時驗證 SHALL 不通過；此保護的加入 SHALL NOT 使既有稽核列的驗證結果改變。操作日誌與調查工作台 SHALL 讓檢視者分辨一筆操作是否經由 API token，以及是哪一把。

#### Scenario: 經由 token 的操作
- **WHEN** 以 token 建立一筆資產後檢視操作日誌
- **THEN** 該列的操作者是所屬帳號，並標示經由哪一把 token

#### Scenario: 寫入交易內留下的紀錄同樣帶標示
- **WHEN** 以 token 變更某個帳號的角色指派，該操作在寫入交易內留下角色異動的稽核列
- **THEN** 請求層級的紀錄與角色異動的紀錄皆標示經由同一把 token

#### Scenario: 排程日後執行的紀錄
- **WHEN** 以 token 建立一筆改密計劃，該計劃之後依排程執行
- **THEN** 建立計劃的稽核列標示經由該 token；排程執行所產生的稽核列沒有 token 標示

#### Scenario: token 標示被竄改
- **WHEN** 一筆經由 token 的稽核列，其 token 識別被直接改成另一把或被清除
- **THEN** 該列的完整性驗證不通過

#### Scenario: 既有稽核列不受影響
- **WHEN** 系統升級加入 token 標示後，對升級前寫入的稽核列執行完整性驗證
- **THEN** 驗證結果與升級前相同

#### Scenario: 親自操作
- **WHEN** 同一帳號以登入工作階段在畫面上修改一筆資產後檢視操作日誌
- **THEN** 該列的操作者是同一帳號，沒有 token 標示

#### Scenario: token 撤銷後的歷史紀錄
- **WHEN** 一把 token 被撤銷後，檢視它先前操作的稽核列
- **THEN** 仍顯示當時的 token 名稱

### Requirement: 角色變動前提示受影響的 API token

管理者變更某個帳號的角色指派時，儲存前的變更預覽 SHALL 指出該變更會使該帳號的哪幾把 API token 失去角色、哪幾把會因此暫停。變更會使某把 token 重新取得它被授權、但目前因帳號沒有該角色而不生效的角色時，預覽 SHALL 指出是哪幾把 token、各自恢復哪些角色，以及哪幾把會因此由暫停恢復為可用；預覽 SHALL NOT 對這類變更表示現有 token 不受影響。預覽 SHALL 說明角色指派回來後這些 token 會自動恢復，以及 token 不會因帳號新增角色而取得未被授權的角色。受影響與否 SHALL 以變更前後該帳號實際有效的角色（含經使用者群組取得的）計算。

#### Scenario: 收回的角色另有群組來源
- **WHEN** 管理者準備收回某帳號直接持有的一個管理類角色，該帳號同時經使用者群組持有同一角色，且有一把授權了該角色的 token
- **THEN** 預覽不把該 token 列為受影響

#### Scenario: 加回 token 被授權過的角色
- **WHEN** 管理者準備把一個管理類角色指派給某帳號，該帳號有一把授權了這個角色的 token，而帳號目前沒有這個角色的任何有效指派
- **THEN** 預覽指出該 token 會恢復這個角色；該 token 原本因授權角色全部不生效而暫停時，預覽另指出它會恢復為可用

#### Scenario: 新增 token 未被授權的角色
- **WHEN** 管理者準備把一個管理類角色指派給某帳號，該帳號沒有任何 token 被授權這個角色
- **THEN** 預覽不把任何 token 列為受影響，並說明現有 token 不會取得這個角色

#### Scenario: 收回一個角色
- **WHEN** 管理者準備收回某帳號的一個管理類角色，該帳號有一把授權了該角色與另一個角色的 token
- **THEN** 預覽指出該 token 會失去這個角色、仍可使用，暫停的數量為零

#### Scenario: 收回全部管理類角色
- **WHEN** 管理者準備收回某帳號的全部管理類角色，該帳號有三把可用 token
- **THEN** 預覽指出三把都會暫停，並說明要永久停止須撤銷

### Requirement: 本人的 API token 畫面

個人資料頁 SHALL 提供 API token 區塊，列出本人的全部 API token 及其名稱、授權角色與範圍、狀態、到期時間、最近使用時間與來源、建立時間，並提供建立與撤銷。建立時畫面 SHALL 只列出本人持有的管理類角色供勾選、預設全選，到期時間 SHALL 由使用者明確選擇而不預選，並在送出前呈現這把 token 能做什麼、只能呼叫管理與設定 API、以及帳號設有允許來源網段時的來源限制。建立完成 SHALL 在同一處呈現明文、複製功能與一段可複製的查驗指令，並說明明文不會再次顯示。沒有建立資格的人 SHALL 看到說明原因與下一步的文字，而不是空白或隱藏的區塊。畫面 SHALL 說明建立後不能修改，要調整須建立新的並撤銷舊的。

#### Scenario: 有建立資格者
- **WHEN** 持有管理類角色的人開啟個人資料頁
- **THEN** 看到 API token 區塊、既有 token 的清單與建立按鈕

#### Scenario: 沒有建立資格者
- **WHEN** 只持有非管理類角色的人開啟個人資料頁
- **THEN** 看到 API token 區塊與一段說明：目前沒有管理權限所以不能建立、應向誰申請

#### Scenario: 選擇永不到期
- **WHEN** 使用者在建立對話框選擇永不到期
- **THEN** 畫面說明這把 token 不會自動失效、不再使用時須自行撤銷，不另加確認步驟

### Requirement: 管理者檢視他人的 API token

使用者詳情頁 SHALL 提供 API token 分頁，讓具帳號管理能力的人查看該帳號的 API token 與各自的授權角色、狀態、到期與最近使用，並能撤銷其中一把或全部。該分頁 SHALL NOT 提供建立功能，並 SHALL 說明只有本人能建立。所屬帳號為受保護帳號而檢視者不是超級管理者時，畫面 SHALL NOT 提供撤銷，並說明原因與應聯絡的對象。

#### Scenario: 管理者查看與撤銷
- **WHEN** 具帳號管理能力的人開啟某個一般管理者的使用者詳情頁
- **THEN** 看到 API token 分頁、清單與撤銷操作，沒有建立按鈕

#### Scenario: 受保護帳號
- **WHEN** 非超級管理者開啟一個超級管理者帳號的 API token 分頁
- **THEN** 看得到清單，沒有撤銷操作，畫面說明只有超級管理者能撤銷
