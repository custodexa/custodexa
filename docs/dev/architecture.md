# 後端模組架構

> 規範權威是 `openspec/specs/module-boundaries/spec.md`（七模組切分、方向性 import 約束、
> 資料表所有權守衛與跨模組交易級聯白名單皆為 SHALL 條文）；本文是它對開發者的導讀。
> 程式碼層的一般不變式見 `docs/dev/conventions.md`，守衛紀律與機械檢查見 `docs/dev/testing.md`。
> 本文只寫「不知道就會做錯」的事：邊界由誰強制、哪些保證不成立、改動時要遵守什麼。

## 1. 七模組與不模組化的部分

後端核心領域是一個**模組化單體**，切分為七個模組，全部位於 `backend/internal/modules/`：

| 模組 | 職責 |
|---|---|
| `keyvault` | KEK/DEK 信封加密與版本化、輪替退休、密文參照登記、封印後置遷移、AAD 哨兵 |
| `policy` | 政策鍵的定義／讀取／快取、存取三段位判定、傳輸通道與同意、密碼政策執法；**所有「可否」判定收斂於此** |
| `audit` | 審計落地（非同步佇列＋三層降級）、完整性蓋章、syslog 轉發、指令告警、通知通道、匯出、保留期硬刪 |
| `asset` | 資產與資產樹 CRUD、資產帳號與憑證封裝／解封、改密、host key TOFU；**憑證明文的唯一產生地** |
| `authz` | 常設授權＋票證授權（申請／核准／break-glass／撤銷）、審核者範圍、有效權限解析、路由級 RBAC 表；**授權寫入兩路徑收斂於此** |
| `identity` | 本地／OIDC／LDAP 三登入路徑、MFA、refresh 輪替、認證世代閘、使用者主檔、local admin 不變式 |
| `session` | 會話生命週期與狀態機、對帳與逾時終結、錄影管理與播放、自助連線視圖、SFTP、命令片段 |

**刻意不模組化（勿順手改）**：共用資料模型包 `backend/internal/model`、
錯誤出口 `backend/internal/apierror`、基礎設施層 `backend/internal/database`、
handler 層，以及六個協議接入包（`sshproxy`／`proxy`／`dbproxy`／`k8sproxy`／`localpty`／`recorder`）。
i18n 維持橫切。

`backend/internal/connectgate` 是**交付層的共用包，不是第八個模組**：它的出向 import 只有
`backend/pkg/gatewayapi`，不持有任何資料、不做任何判定，只負責「依序評估閘、第一個拒絕即短路」。
閘的判定本體留在各交付層自己的 `connect_gates.go`。

兩條劃分鐵律：**劃分單位是「宣告」而非「檔案」**（同一檔內的宣告可能分屬兩個模組，
該檔就必須拆）；**型別的方法必須與型別同包**。

## 2. 隔離只有三層，強度各不相同

「模組化」在本專案的準確意思是**有方向性 import 約束的程式碼分區**。實際成立的隔離如下表，
超出此表的宣稱（資料封裝、bounded context、語言級可強制的模組隔離）皆不成立：

| 層 | 由誰強制 | 實際保證 |
|---|---|---|
| 跨 package 識別字可見性 | **Go 編譯器** | 未匯出符號跨模組不可見 |
| 禁止的直接 import 邊（方向矩陣） | **守衛測試** `backend/internal/guards/moduleboundary/module_import_graph_guard_test.go` | 只擋登記為禁止的邊；合法方向上，模組仍可使用彼此**任意已匯出的具體 API**，不限於窄 port |
| 窄 port／資料存取權限 | **未強制** | 共用 `internal/model` ＋各模組直接持有 ORM 句柄，資料層可完全繞過 port；僅由 ratchet 登記表記帳（現況以 `backend/internal/guards/moduleboundary/module_data_boundary_registry_test.go` 為準，本文不複述列數） |

把方向矩陣說成「編譯器可證」是不準的：Go 編譯器只保證跨 package 不能引用未匯出識別字，
它**不禁止**合法方向上的模組直接使用彼此的任意匯出 API。方向矩陣是由一支**測試**維持的，
不是語言級隔離。

## 3. 誠實邊界（宣稱時不得越過）

這一節是防止宣稱過度的關鍵。以下每一條都是已知落差，不是待辦：

- **交出交易物件的路徑不受編譯器保護**：跨模組交易級聯寫入以「呼叫方宣告窄介面、
  組裝層注入擁有者實作」表達，並登記於
  `backend/internal/guards/txtaking/tx_taking_whitelist_test.go` 的具名白名單（無理由的登記會紅）。
  白名單只保證「哪些呼叫點把交易交出去」被登記且被審視過，**不保證交出去之後發生了什麼**。
- **收口會讓耦合自掃描面上消失**：跨模組寫入收斂為擁有者模組的方法後，掃描器判為
  「自己寫自己」。**資料邊界 ratchet 的數字變小不等於耦合消失**，判讀時必須與交易白名單一起看。
- **兩側不對稱**：部分呼叫方確實達成「不 import 擁有者模組」，部分只是窄化了寫入面
  （擁有者模組在方向矩陣上本就是合法出向）。不得等量齊觀。
- **SQL 層耦合驗不出來**：JOIN／關聯載入造成的耦合、以及共用資料模型包作為公共匯流排的
  可繞過性，型別系統都無從驗證。
- **runtime backstop 的稱謂**必須是「**ORM callback 路徑上的**最終權威」，
  **不得無條件稱**「每個 fail-close 點的最終權威」。四個盲區（原生 SQL、Update callback 路徑、
  另行開啟的新 DB 句柄、非 ORM 寫入）已用邊界測試釘住，使盲區**可見而非隱形**。
- **非同步審計 sink 是 at-most-once**：在事件 ID、至少一次投遞、消費端去重與 durable-accept
  四項演進前提全數完成前，**SHALL NOT** 把任何 fail-close 需求改掛到非同步 sink。
- **閘的 `Stage` 標記不構成機器約束**：`connectgate` 的骨架不會因為某道閘登記在別的階段而拒絕執行它。
  受機器強制的不變式只有一條：**憑證解封夾在兩次授權呼叫之間**。文件與 spec 對 `Stage` 的敘述
  SHALL NOT 寫成保證。
- **守衛之間存在相關失效**：多道守衛共用同一批掃描器辨識「什麼算一個事件」，掃描器看不見的效果，
  登記表也不會知道自己缺了一列。逐類別的現況（哪些有名稱無關 oracle、哪些接受風險）
  登記在 `docs/dev/testing.md` 的同源 oracle 對照表——新增關鍵效果類別時要同步加一列。
- **登記表證不了語義**：同一個已登記的呼叫點可被改綁到 no-op sink、改變交易語義，
  或把副作用搬進 helper，而清單完全一致、守衛全綠。**機械完備性 SHALL NOT 被讀成行為完備性。**
- **守衛可被有 commit 權者刪除**：這些邊界在型別系統上不存在，只能靠守衛測試＋審查維持。
  契約須誠實標註此落差，**不得固化為「設計如此」**。

## 4. 常駐約束（任何改動都適用）

1. **不得新增跨模組 import 邊，也不得繞過方向矩陣。** 新增邊是設計決策，須先改守衛的允許表
   並說明理由，而不是把測試改綠。合法方向上請優先用窄 port／消費者側介面，
   不要機械式把符號改成大寫匯出。
2. **動到審計寫入或啟動／關閉順序，先改登記清冊。** 審計寫入點與生命週期兩份清冊是雙向完備的
   （程式碼多一個未登記的產生點會紅，清冊多一列不存在的也會紅），路徑與守衛檔見
   `docs/dev/conventions.md` 的審計寫入與啟停順序兩節。**方向是先登記再改碼**；
   反過來把清冊改成遷就程式碼，等於把守衛降級為記錄工具。順序敏感的三個危險點
   （蓋章 hook 早於任何審計寫入、告警推送器的 LIFO 前提、金鑰 zeroize 位置）
   失敗形態全部是「安靜」的。
3. **fail-close 的地方不得順手改成 log-and-continue。** 交易內審計寫入失敗 SHALL 回滾整筆業務交易。
   這類退化的特徵是**改完測試更綠**，所以它由 runtime 故障注入 backstop 而非閱讀把關。
4. **搬檔或改 package 前跑三項機械必查**（守衛射程隨搬檔改變／掃描根去耦／測試名集合差集），
   步驟與踩過的坑見 `docs/dev/testing.md`。
5. **宣稱前讀第 3 節。** 對外文件與 spec 一律不得把方向性 import 約束寫成資料封裝或模組隔離。

**要動這個結構本身時**（例如拆共用資料模型包、把某模組再拆、或處理第 3 節的落差）：
先確認你要解的是不是第 3 節已經登記過的同一個問題，再讀 `openspec/specs/module-boundaries/spec.md`
與 `docs/dev/conventions.md`；動手前先跑 `docker compose exec -T backend go test ./... -count=1`
取得**你自己動手前**的基準（測試名集合與路由 golden 的 SHA256），驗收時比對這個基準而不是比對記憶。
