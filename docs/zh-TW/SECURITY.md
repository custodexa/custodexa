# 安全問題回報

> 本檔為英文版 [SECURITY.md](../../SECURITY.md) 的中文對照。若有歧異，以英文版為準（它是對外回報管道的權威文本）。

## 請不要開公開 issue

發現安全問題時，請走 GitHub 的**私密漏洞回報**：

**[提交私密回報](https://github.com/custodexa/custodexa/security/advisories/new)**
（repo 的 Security 分頁 → Report a vulnerability）

這條管道只有維護者看得到，回報內容在公告發布前不會外流。
本專案是特權存取管理產品，公開的 issue 等於把攻擊方法直接交到所有部署環境的攻擊者手上。

## 回報時請盡量附上

以下是**希望有**，不是**必須有**；缺項不會被拒收：

1. 受影響的版本或 commit
2. 涉及的元件與協議（SSH／RDP／VNC／資料庫 CLI／K8s exec／Web 管理介面／API）
3. 重現步驟（最好附上最小可重現環境）
4. 影響：攻擊者能做到什麼、需要什麼前置權限
5. 你希望的署名方式（或不具名）

**請勿附上真實環境的憑證、個人資料或客戶資料。**
若重現必須依賴特定資料，描述它的形態即可，不要貼原文。

## 測試時請遵守

- 只測試**你自己擁有、或已取得書面授權**的部署。本專案沒有公開測試環境，
  也無法代任何第三方授權你測試他們的部署。
- 不破壞資料、不取用非測試資料、不做阻斷服務壓測。

## 你可以期待什麼

**本專案不提供回應時限（SLA）承諾。** 這是刻意的：本專案由個人維護，
「24 小時內回應」「7 日內修補」這類數字沒有承擔者，寫上去只是一句無法履行的話。

取而代之的是明確的**處置順序**：

| 級別 | 處置 |
|---|---|
| **Critical** | 中斷當下所有工作，優先於任何功能開發 |
| **High** | 排在下一個工作批次之前，不與功能項競爭排序 |
| **Medium／Low** | 進 backlog，與其他安全項一併排期 |

已在野外被利用、或 PoC 已公開的問題，一律提升一級處置。

### 怎麼定級

不採用 CVSS 分數作為判準。本產品是連線收口型系統，同一個技術缺陷的實際後果
高度取決於「攻擊者是否已經在管理面內」「該路徑能否從未認證入口到達」，
而這正是 CVSS 基礎分最弱的部分。你提供 CVSS 向量我們會記錄，但定級以三軸為準：

- **可達性**：未認證即可觸發？需一般使用者？需管理員？需已在主機上？
- **前置條件**：需要特定組態或部署形態？預設組態會不會命中？
- **後果**：憑證外洩／繞過連線收口／繞過審計或錄影／提權／阻斷服務／資訊揭露

**分級不會因為「修起來很難」而下調。** 難修的處置方式是揭露緩解措施，不是改分級。

### 「不修」也是一種正當結論

判定不修是正當的結論，但一定會說明理由。典型的正當理由是：前提不成立
（回報建立在對行為的誤讀上）、落在威脅模型之外（例如「持有簽章私鑰的管理者可以重簽」，
那是規格內已明載的邊界）、或已有等效的補償控制且該控制寫在營運文件裡。

## 公開揭露

**修補釋出前請不要公開細節。**

若自你回報起 **90 日**內仍未有修補釋出，你可以自行公開，不需要再徵詢同意。
這是**你的權利，不是本專案的時限承諾**：本專案不保證 90 日內修得完，
但也不會用「還沒修好」把一個已知問題無限期壓在你手上。

修補釋出後，會以 **GitHub Security Advisory** 公告，內容包含影響範圍、
受影響版本、緩解方式，以及（除非你希望不具名）回報者署名。
需要 CVE 編號時透過 GitHub 申請。

## 本專案沒有的東西

列在這裡，免得你白費力氣：

- **漏洞獎金（bug bounty）**：沒有，也沒有計畫。
- **正式的法律保護聲明（safe harbor）**：沒有。本專案由個人維護，無法提供有法律效力的保證。
  維護者不會對遵守上述規則的善意回報者採取行動，但這是說明立場，不構成法律承諾。
- **公開測試環境**：沒有。請在你自己的部署上測試。

## 已知的依賴狀況

**MSSQL 連線用的 `sqlcmd` 內嵌的函式庫版本落後。** 本專案自上游（微軟 go-sqlcmd）
的**源碼**建置該執行檔（`docker/backend/Dockerfile` 的 `sqlcmd-builder` 階段，
釘定 `v1.10.0`），而 v1.10.0 是其最新發行版。**其相依樹由上游的 `go.mod` 決定，
本專案不介入**：單方面提版會偏離上游驗證過的組合，屬於自行維護一份分支，
故採「跟隨上游發行版」的立場，須待上游更新。

**能判定的**：多數告警落在本專案不使用的功能路徑（SSH 連線、容器管理子指令）。

**不能判定的**：對該執行檔不存在可靠的可達性分析方法。
掃描工具比對的是套件版本而非實際呼叫路徑，而建置以 `-w -s` 剝除符號表。
**因此本專案不宣稱這些告警無害。**

**現有的結構性限制**（每次建置皆機械斷言，非承諾）：該執行檔以降權身分執行、
無可寫路徑、無 setuid，正式版映像不含 shell。

不使用 MSSQL 連線功能者不受此影響。

RDP／VNC 用的 guacd，其基礎系統已停止安全更新；該狀況與其部署影響見
[部署形態限制](../ops/deployment-topology-limits.md)。

## 支援的版本

1.0 發佈後，安全修補只釋出於**最新的次版本**。舊次版本不做 backport；
本專案沒有足以維護多條分支的人力，承諾了也做不到。
